Skill 不是文档，是给 agent 的状态机

把 .claude/skills/ 下三个真实 skill 当样本，反推怎么写一个 agent 会用、不会绕过、不会乱触发的 Skill。

v0 · 2026-04-25 主题：Skill 最佳实践 样本：onboard / explore-mode / ship 纯静态 mock 数据

01关键发现

F1

触发 ≠ 标题

description 字段必须列触发信号词（"做一个 demo / 试想法"），靠标题猜永远会漏。

F2

流程 ≠ 解释

把"用户说 → 默认理解 → 默认动作"做成表格，比写一段散文有效一个数量级。

F3

边界 ≠ 提醒

用 ✓ ✗ ⚠ 三个符号显式列允许/禁止，比"请注意"自然语言更难被 agent 忽略。

02三大设计原则

🎯

原则一：触发设计——把 description 当路由器写

agent 选不选你的 skill，只看 description 一行。要把用户原话级的触发词列进去，否则永远漏触发。

反例改进
"用于探索期工作" "做一个 demo / 试一个想法 / 我想验证 / 实验一下"
"帮助提交代码" "上传 / 提交 / 推上去 / 交差"（口语 + 同义词）
⚙️

原则二：流程要可机械执行——schema 化，不靠 reasoning

每一步都要有明确输入、明确判断、明确动作。复杂分支用表格而不是嵌套段落。

步骤判断动作
读 $DEEPINSIGHT_HANDLE 空？ 提示 init-explore，停止
检查 explorations/$HANDLE/ 不存在？ 同上
写文件 路径是否在 $HANDLE 下？ 否则反问意图
🚧

原则三：边界要符号化——✓ ✗ ⚠ 三个符号即可

自然语言的"请避免"在 agent 眼里是软建议；显式的禁止符号更难被绕过。配 hook 兜底，构成"规范 + 强约束"双层。

符号语义样例
✓显式允许explorations/$HANDLE/**、docs/**
✗显式禁止web/**、explorations/<other>/**
⚠注意条件不调真 LLM API（前期纯静态）

04反模式画廊

✗

description 写抽象愿景

"帮助你更好地探索"——agent 读不出何时该路由进来。

✗

一个 skill 塞多种能力

"探索期 + 提交 + 部署"合一份 → 触发条件互相干扰，宁可拆三份。

✗

流程靠"请你"

"请确认代号"vs."读 $DEEPINSIGHT_HANDLE，空则停止" — 后者 agent 不会理解错。

✗

边界只在 README 提一句

规范要在 skill 内 + hook 兜底两层。只写一份等于没写。

✗

没列反例

"反模式" section 是验证 skill 写得够不够具体的试金石——写不出反例，说明流程也没具体到位。

✗

不写收敛/失效条件

探索期 skill 应说明"2026-05-09 后失效"，否则会留作技术债污染未来 agent 行为。

05证据 · 自指

本次洞察的最强样本就是本仓库的 explore-mode.md 自己。
它在 .claude/skills/explore-mode.md:10-18 列了 6 条触发信号词， 在 :42-48 用「用户说 / 默认理解 / 默认动作」三列表， 在 :51-54 用 ✗ / ✓ / ⚠ 列了 3+1 条边界， 在 :84-89 列了 4 条反模式， 在 :91-93 写了"收敛日 2026-05-09 失效"。
—— 这正是本页提炼出的全部三大原则的实例。也是为什么阿栋这次直接被 skill 引导着完成了 init。
